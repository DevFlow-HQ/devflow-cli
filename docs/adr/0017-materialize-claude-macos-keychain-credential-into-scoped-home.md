# Materialize Claude's macOS Keychain Credential into the Scoped Provider Home

DevFlow runs every Claude **Managed session** under a run-scoped `CLAUDE_CONFIG_DIR` (the **Scoped provider home**) to isolate JSONL logs and hook settings per run (ADR-0006, ADR-0008). On macOS this silently breaks authentication: Claude consults the OS Keychain credential **only for the default install location**, and the moment `CLAUDE_CONFIG_DIR` points elsewhere it stops reading the Keychain and instead reads a file, `$CLAUDE_CONFIG_DIR/.credentials.json`. DevFlow never wrote that file on macOS (`seedClaudeCredentials` early-returned on `darwin`, on the now-disproven assumption that the Keychain is global), so a scoped session had no credential source and dropped into "Not logged in · Please run /login". Verified empirically with `claude -p`: a byte-for-byte copy of `~/.claude` at a custom path stays "Not logged in", while writing a (bogus) `.credentials.json` into the scoped dir flips the error to "401 Invalid bearer token" — proving macOS Claude *does* read the credential file from a custom config dir.

**Decision.** On macOS, DevFlow reads Claude's OAuth credential from the Keychain (generic password, service `Claude Code-credentials`, account = the macOS username) via the `security` CLI and writes it verbatim into `<scopedHome>/.credentials.json` at mode `0600`. The credential is deleted during **Completed-session cleanup** (the ADR-0014 teardown path), bounding the secret's on-disk lifetime to the session. Linux keeps its existing source-file copy unchanged; the platform branch lives inside `seedClaudeCredentials`. The Keychain access is encapsulated in one deep, dependency-injected module (`readMacosKeychainCredential`) so the subprocess knowledge does not leak into the seeding logic and every branch is unit-testable without a real Keychain.

**Trade-offs.** This deliberately materializes a plaintext OAuth token to disk — weaker than the Keychain's guarantees, and surprising to a reader who would expect macOS credentials to stay in the Keychain, hence this record. We accept it because: the file lands only under `.devflow/` (already gitignored, never committed), is written owner-only (`0600`), and is removed on session completion; it reuses the exact credential mechanism Linux already relies on; and it is the only way to keep the per-run `CLAUDE_CONFIG_DIR` isolation that ADR-0006/0008 require while still authenticating. The considered alternative — *not* scoping `CLAUDE_CONFIG_DIR` so the Keychain works — was rejected: it reopens ADR-0006/0008 and sacrifices JSONL/hook isolation to avoid writing a secret that is already gitignored and short-lived. One operational note: the first time the DevFlow (node) process reads the item, macOS may show a one-time GUI "allow access" prompt; the user clicks "Always Allow" once. A missing Keychain credential is not an error — DevFlow writes nothing and lets Claude surface its own not-logged-in path.
